# Web Layer — Human CAPTCHA Benchmark Application

The `Web/` application is the presentation, interaction, and participant benchmarking layer for the CAPTCHA challenges generated by `Challenges/`.

It allows human participants to browse visual perception challenges, inspect stimuli, interact with challenge controls, submit answers, and receive instant server-validated correctness feedback along with high-precision solve times.

---

## 1. Core Principles & System Boundaries

- **`Challenges/` is the exclusive Source of Truth:** `Web/` consumes pre-generated, validated challenges from `Challenges/generated/`. It **never** generates, mutates, crops, re-compresses, or re-interprets challenge data.
- **Strict Public vs. Private Data Isolation:**
  - **Public Data (`public/challenges/`):** Contains only participant-safe data: `challenge.json` (neutral assets, grid definitions, instructions) and visual stimuli.
  - **Private Data (`src/generated-private/`):** Contains ground-truth answers (`correctSelection`, `answer`). Synced into a server-only module bundled for server-side evaluation. **`answer.json` is never copied to `public/`**.
  - **Zero Leakage:** Automated audit checks fail the build if any ground-truth fields or target hints appear in public assets.
- **No AI in Web:** `Web/` is strictly for human participants. The `AI-Solver/` system will interact via independent evaluation pipelines later.
- **No Persistence / Database Yet:** Benchmark results are computed and displayed live. No database (D1, KV, R2) is required at this stage.

## 2. Tech Stack & Cloudflare / OpenNext Architecture

- **Framework:** Next.js (App Router, React 19, TypeScript)
- **Adapter:** `@opennextjs/cloudflare`
- **Deployment Target:** Cloudflare Workers with `nodejs_compat` compatibility flag
- **Configuration Files:**
  - [`open-next.config.ts`](./open-next.config.ts): Cloudflare OpenNext configuration using `defineCloudflareConfig({})`.
  - [`wrangler.jsonc`](./wrangler.jsonc): Cloudflare Workers configuration with `.open-next/worker.js` entrypoint, `nodejs_compat`, and assets binding.
  - [`next.config.mjs`](./next.config.mjs): Next.js configuration with `initOpenNextCloudflareForDev()`.

## 3. Build-Time Synchronization Pipeline

Because Cloudflare Workers execute in a sandboxed V8 / workerd environment without filesystem access to parent directories (`../Challenges/generated/`), all challenge data is ingested at build time via:

```text
Challenges/generated/
        │
        ▼
Web/scripts/sync-challenges.ts
        │
        ├──► Web/public/challenges/
        │     ├── catalog.json          # Public navigation catalog (NO answers)
        │     └── <challengeId>/
        │           ├── challenge.json  # Neutral client challenge definition
        │           └── assets/*.webp   # Neutral image stimuli
        │
        └──► Web/src/generated-private/
              ├── answers.json          # Private server-only ground truth
              └── answers.ts            # Typed server registry module
```

Before syncing, the script cleans only previous Web-generated assets. It never touches `Challenges/`.

## 4. Challenge Structure & Components

| Level | UI Label | Variant Key | UI Component | Description |
| :--- | :--- | :--- | :--- | :--- |
| **Level 1** | Normal CAPTCHA | `street-grid` | `ImageGridChallenge` | $3\times 3$ grid of easy real BDD100K daytime street scenes |
| **Level 2A** | Hard CAPTCHA | `hard-street-grid` | `ImageGridChallenge` | $4\times 4$ grid of difficult BDD100K street scenes (night/glare/distance) |
| **Level 2B** | Visual Illusion | `checker-shadow` | `BinaryChoiceChallenge` | Adelson Checker Shadow illusion ("Yes" / "No") |
| **Level 3A** | Tangled Cables | `tangled-cables` | `TangledCablesChallenge` | Procedural network patch panel with zoomable canvas & port keypad |
| **Level 3B** | Degraded Vision | `degraded-vision` | `ImageGridChallenge` | Multi-resolution downsampled street scenes (`64, 48, 32, 24, 16, 12, 8`) |

## 5. Web Routes

- **`/`**: Home landing page with experiment overview and quick CTAs.
- **`/challenges`**: Level select overview presenting all 5 levels with challenge counts and progression flow entry.
- **`/challenge/[challengeId]`**: Universal challenge play route that dynamically mounts the appropriate UI interaction component based on variant.
- **`/api/challenges/[challengeId]/submit`**: Server Route Handler performing secure ground-truth grading against `ANSWERS_REGISTRY`.

## 6. Development & Build Commands

### Install Dependencies
```bash
npm install
```

### Synchronize Challenges (Build-Time Pipeline)
```bash
npm run challenges:sync
```

### Development Server
```bash
npm run dev
# Synchronizes challenges then starts Next.js dev server on http://localhost:3000
```

### Production Build
```bash
npm run build
# Synchronizes challenges then builds optimized Next.js app (SSG for all 73 challenges)
```

### OpenNext Cloudflare Worker Build
```bash
npm run build:worker
# Adapts Next.js standalone build for Cloudflare Workers (.open-next/worker.js)
```

### OpenNext Local Preview (Wrangler)
```bash
npm run preview
# Syncs -> Builds Cloudflare worker -> Launches Wrangler local runtime on http://127.0.0.1:8787
```

### Run Tests & Leak Audits
```bash
npm test
# Runs Vitest suite covering sync, zero-leak audit, answer grading, and catalog queries
```

### Cloudflare Deployment (When requested)
```bash
npm run deploy
```

## 7. Future AI-Solver Integration Boundary

The `AI-Solver/` system will run independently. Later, it will receive the same public challenge contracts (`challenge.json` + `assets`) and submit answers via dedicated benchmark endpoints. The strict held-out benchmark split guarantees AI models trained on BDD100K `train` split have zero contaminated exposure to challenge benchmark data.
